# Seguridad y datos

Esta publicación contiene código y ejemplos de demostración. No incluye credenciales, bases de datos personales, configuración privada de firma ni historiales de conversaciones.

- Conserva los secretos en archivos locales ignorados o en un gestor de secretos.
- Los archivos de ejemplo deben contener únicamente valores ficticios.
- No adjuntes datos personales, tokens, trazas de sesión ni respaldos a issues o pull requests.
- Si detectas una credencial expuesta, revócala o rótala antes de limpiar su historial.
- Para reportar una vulnerabilidad, usa la opción privada «Report a vulnerability» del repositorio cuando esté habilitada. No publiques instrucciones con datos reales.

Se revisó el contenido preparado con Gitleaks y comprobaciones locales de archivos y configuración. El análisis estático no garantiza ausencia de vulnerabilidades ni sustituye una auditoría de un despliegue real.
